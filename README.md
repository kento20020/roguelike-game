# カジノタワー ローグライト

確率ベースの戦闘を核にした、**カジノタワーを登り詰める** 5フロアのパーマデス制ローグライト。
薄暗い賭博都市のタワーを舞台に、下の卓から相手を選んで勝ち上がり、各フロアの「胴元の関門（GATE）」を突破して頂上（5F）を目指す（マップは下から上へ登る Slay the Spire 型）。

設計の軸は3つ。

- **ギャンブルの質感** — 攻撃のたびに相手が確率で反応する（反撃・強打・蓄積・空振り）。確率は数値で見せず、色と「傾向」だけを質感として開示する暗黙知型
- **攻めと守りのリスク選択** — チップで「リスクを減らす」ことも「リスクを取って攻める」こともできる。ただし**お金で確実な突破は買えない**
- **パーマデス** — HP0 で全てを失う一回性の緊張感。クリアだけが恒久強化ポイントを生む（win-to-progress）

## 遊び方

各フロアはランごとにランダム生成される「卓のマップ」。下の行から相手を選び、勝ってアンロックを連ねて最上段の**関門（GATE）**を目指す。フロアは上に行くほど深くなり（1F: 2行 → 5F: 6行）、行と行のつなぎは**あみだくじ状**にランごとに変わる。未探索の卓は名前も体力も伏せられ、「傾向」だけが見える。

| 操作 | 内容 |
|------|------|
| **ノードを選ぶ** | 枠が光る卓だけ選択可能。敵=偵察→戦闘 / 宝箱=技を入手 / 控え室=回復 / 関門=フロア突破 |
| **攻撃 / 受け** | 戦闘の基本選択。攻撃は与ダメ大・相手の反応を引く。受け（guard）は与ダメ半減・被ダメ大幅軽減で、読みが当たれば強い |
| **サイドベット** | 攻撃/受けに加えて「次に敵はこの行動をする」と宣言してチップを賭けられる。的中で3倍。戦闘結果そのものには影響しない独立の賭け |
| **Chips Sink** | チップ消費アクション。スカウト（次ターンの最頻行動ヒント）/ 小回復 / 大回復 / 攻撃ブースト、関門では出目テーブルを有利にする「ゲート保証」 |

戦闘中は敵の隣に「気配」（テル）が表示され、その敵がどれくらい読みやすいタイプかが分かる。勝てば次の卓がアンロックされチップを獲得。深い行の敵ほど強く、報酬も多い。関門は戦闘ではなく**出目の抽選**で、大成功/成功/失敗/大失敗のテーブルを引く。5F の関門を抜ければ勝利、HP0 なら敗北＝そのランの全てを失う。

### 体験タイプ（相手の傾向）

全36体の敵がいずれかの傾向に属する。数値は伏せられ、色とアイコンだけが開示される。

| 傾向 | 色 | 主行動 | 性格 |
|------|----|--------|------|
| 削り合い (grind) | 青 | 反撃 | じわじわ削る・堅実 |
| 賭け (gamble) | 赤 | 強打/空振り | 大当たりか空振り |
| レース (race) | 金 | 蓄積の一撃 | 長引くほど重い |
| ずれ (dodge) | 緑 | 回避 | 攻撃を空振りさせる |
| カオス (chaos) | 紫 | 複合 | 予測不能（ラン毎に変動） |

### 技（mod）

プレイヤーは技を持たずに開始し、1F の確定宝箱で **反射** を必ず入手する。以降は宝箱から 見切り / 重装甲 / 好機 / 先読み / 加速止め（全6種）を入手・強化できる。先読みは敵の次の行動を確定公開する唯一の技で、サイドベットとの相性が良い。

### 死んだ後・ランの間

- **検死レポート＆リプレイ** — 死亡時、致命傷のターンに「実は何が起きていたか」（回避不能だった/受けていれば生きていた/攻め続ければ勝っていた）を開示し、全ターンのリプレイで振り返れる
- **ディーラー調書** — 自分がこれまでのランで実際に見た敵の行動頻度が記録される。真の確率表ではなく「自分の体験の統計」で、観測が少ない敵ほど目安の幅が広い
- **恒久強化** — クリアで得たポイントを HP・攻撃などの恒久強化に割り振り、次のランを有利にする

## アーキテクチャ

**React（表示）＋ FastAPI（全ロジック）** のモノレポ。最大の特徴は**サーバ権威**であること——乱数・ダメージ・マップ生成を含む全ての計算は Python 側で行い、React は返ってきたゲーム状態を表示するだけ。クライアントを信用しないため、未来の乱数や未探索の敵情報がフロントに漏れない。

```
┌────────────────────────────────────────────────────────┐
│ ① フロント (Frontend) — React + TypeScript + Vite      │
│    Zustand（状態管理）/ Tailwind（見た目）/             │
│    gameApi.ts（API通信を集約）                          │
│    ※ 計算しない。バックが返す結果を表示するだけ         │
└─────────────────────────┬──────────────────────────────┘
                          │ REST API (HTTP / JSON)
                          ▼
┌────────────────────────────────────────────────────────┐
│ ② バック (Backend) — Python + FastAPI                  │
│    GameEngine（全ロジック）/ FloorGenerator（マップ生成）/│
│    CombatResolver（戦闘）/ GateResolver（関門）          │
│    ※ API と bot シミュレーションが同じエンジンを共用     │
└──────┬─────────────────────────────────┬───────────────┘
       │ 読み込み（起動時・参照）          │ 永続化（SQLAlchemy / Alembic）
       ▼                                 ▼
┌──────────────────────────┐  ┌───────────────────────────┐
│ ③ データ (Data)           │  │ ④ データベース (Database)  │
│   backend/app/data/*.json │  │   SQLite (game.db)         │
│   config / enemies(36体) / │  │   プレイ統計・操作履歴・    │
│   mods(6種) / floors(5F)  │  │   恒久強化・観測記録        │
│   ※ 数値の正本・読み取り専用│  │   ※ 実行時に書き込み        │
└──────────────────────────┘  └───────────────────────────┘
```

**支えている仕組み:**

- **同一エンジンの二重利用** — 人間が遊ぶ API と、バランス検証用の bot シミュレーションが同じ `GameEngine` を呼ぶ。UI 用と検証用でロジックが食い違わない
- **seed 決定論** — 乱数は SFC32 を用途別の9本の独立ストリームに分けて管理。同じ seed なら何度でも同じランが再現される（マップ・敵の行動・関門の出目まで）
- **データが正本** — 戦闘係数・敵36体・技6種・フロア構成の数値はすべて `backend/app/data/*.json` に集約。コードは数値を持たない
- **マップの構成的生成** — フロアのあみだくじ構造は「多親は必ず隣接2親・全ノード到達可能」といった制約を、リトライではなく**生成手順そのものが保証する**アルゴリズムで作られる
- **完全状態レスポンス** — API は毎回ゲームの完全な状態を返し、フロントに差分計算をさせない

## 起動方法

```
# backend（FastAPI / 全ロジック）— http://localhost:8000
cd backend && pip install -r requirements.txt && uvicorn main:app --reload

# frontend（React / 表示）— http://localhost:5173
cd frontend && npm install && npm run dev
```

## ディレクトリ構成

```
.
├── backend/           # FastAPI（全ロジック）
│   └── app/
│       ├── data/      # 数値の正本 JSON（config / enemies / mods / floors）
│       ├── engine/    # ゲームエンジン（戦闘・マップ生成・関門・乱数）
│       ├── api/       # REST エンドポイント
│       ├── db/        # SQLAlchemy モデル・永続化
│       └── simulation/# bot シミュレーション（バランス検証）
├── frontend/          # React（表示のみ）
│   └── src/           # api（通信集約）/ store（Zustand）/ pages / components
├── docs/              # 設計書（正本）
└── design/            # 画面デザインのプロトタイプ
```
