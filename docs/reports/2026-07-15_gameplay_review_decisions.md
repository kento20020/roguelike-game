## 1. 経緯 — レビューで挙がった懸念

ゲーム性・面白さに絞った外部視点レビューの要旨。テーマとメカニクスの一致・思想の一貫性は高評価の一方、以下の5点が「遊びとして詰まりうる箇所」として指摘された。

| # | 懸念 | 要旨 |
|---|---|---|
| ① | 攻撃／受け2択の支配戦略化 | 多くの敵で「ずっと攻撃」が期待値最適になると、看板の読み合いが死ぬ。面白さの生命線だが設計書上は数値任せ |
| ② | カオスと「知識が報われる」柱の矛盾 | 学習が効かない敵は、数が多いと読み合いゲーのノイズになる |
| ③ | win-to-progress の離脱リスク | 初クリアまで恒久報酬ゼロ。中央値プレイヤー（8〜15分で死ぬラン主体）が壁で離脱しうる |
| ④ | ゲートが純RNGの一発ロール | フロアを技術で勝ち抜いた直後に、技能が一切関与しない出目で最大HP18%を失う。「頑張りが無効化される瞬間」 |
| ⑤ | 読み宣言（サイドベット）が浮く | 戦闘結果に影響しない独立の賭けは、多くのプレイヤーに無視され「あってもいい要素」止まりのリスク |

このほか細部として「1Fの単調さ」「36体の個体差（タイプ内の癖の立ち方）」「調整目標の数値レンジが未定義」が指摘された（→ §5 保留事項）。

## 3. 登攀ポイント制（climb-to-progress）— 確定仕様

### 3.1 現行仕様（変更前の正本値）

`config.json` `permanent_upgrades`: `points_per_clear: 1`、各レベルのコストは一律1ポイント。
21レベル（5Lv枠×3＋3Lv枠×2）＝満額21クリア。**クリア以外でポイントを得る手段はない。**

### 3.2 獲得ルール（決定）

- **ゲートnのロール解決時に nポイント** を付与する（1F=1, 2F=2, … 5F=5。全ゲート通過＝15）
- **ゲートのロールの被ダメージで死亡しても、そのゲートの分は付与する**（「勝負はやり切った」— ④の不満の瞬間を直接緩和）
- **クリア（5F通過）で追加 +10** → クリアラン合計 **25ポイント**
- 死亡画面に「今回の登攀: +Xポイント」を検死レポートと並置して表示する — すべての死が目に見える持ち帰りを生む（③の核心）

### 3.3 コスト曲線（決定: 初期値3・トラック内乗数×2）

| トラック | コスト列 | 枠計 |
|---|---|---:|
| max_hp / attack / init_gold（5Lv枠） | 3, 6, 12, 24, 48 | 93 |
| gold_drop / sink_cost（3Lv枠） | 3, 6, 12 | 21 |

- 満額総計 **321ポイント ≈ クリア13回ぶん**（現行21回から緩和。序盤加速を優先したデザイナー判断）
- 乗数はトラック内で独立に適用する（全購入通算の乗数は総コストが指数爆発するため不可）

### 3.4 設計検証

**周回耐性 — なぜ「乗数コスト×階層比例獲得」の組で成立するか**
乗数コスト単体は周回対策にならない（全員が等しく遅くなるだけ）。周回より登攀を得にする本体は獲得側の階層比例で、役割分担は次の通り。

- 階層比例の獲得 → 深いランは浅い周回の15〜25倍のポイント効率（「上の階まで上がるメリット」の本体）
- 乗数コスト → 後半レベルは大口ポイントが必要になり浅い周回では現実的なラン数で届かない。かつ序盤レベルは安く、初クリア前でも買える（③の解決）

検証値: 2F止まり周回（1pt/ラン）で満額321ラン vs 登攀約13クリアラン＝**効率差25倍**。ラン内の獲得はゲート5個で頭打ちのため時間グラインドも効かない。

**プレイヤー像別の体験**

| プレイヤー像 | 1ランの獲得 | 対クリア比 | 備考 |
|---|---:|---:|---|
| 1Fで死亡（ゲート0個） | 0 | — | |
| 2Fで死亡（ゲート1個） | 1 | 4% | |
| 3Fで死亡（中央値層） | 3 | 12% | **1ランで初購入（3pt）に到達** |
| 5Fで死亡（あと一歩） | 10 | 40% | |
| クリア | 25 | 100% | |

**思想面の整合**
「win-to-progress」の哲学は「climb-to-progress」へ改訂する。グラインド排除の論拠は保存される — 報われるのは「プレイ時間」ではなく「到達階層」であり、到達階層は腕でしか伸びないため「腕と強化の両輪」も維持される。

### 3.5 決定の経緯（選択肢と採否）

| 論点 | 候補 | 決定 |
|---|---|---|
| コスト曲線 | A: 5,10,20,40,80（満額≈21回・現行ペース維持）／ B: 3,6,12,24,48（≈13回）／ C: 3,8,19,47,117（≈26回） | **B**（序盤加速。満額到達が現行より早まる点は了承済み） |
| ゲート死亡時の付与 | 付与する ／ 付与しない | **付与する**（④の緩和を優先） |
| クリアボーナス | 0 ／ +10 ／ +20 | **+10**（5F死亡10ptとの差2.5倍でクリアの特別感を確保） |

なお④の「技術がロールに関与しない」問題そのものは本案では解消しない（納得感側の緩和策）。確率を変えない演出改善（出目の段階開示）は独立オプションとして保留（§5）。

## 4. その他の決定仕様

### 4.1 ①B — 攻撃支配の不成立をbotシミュの合格条件に

`phase12_harness` に指標を追加し、balance_model に「調整目標（合格条件）」節を新設する。

- 「常に攻撃」bot と「最適に受けを混ぜる」bot の勝率差・平均残HP差が合格レンジ内であること
- 最適botの受け使用率が敵タイプ別の下限を割らないこと
- 閾値レンジは初回シミュレーション実行後にデザイナーが設定（それまで仮値と明記）
- CLAUDE.md の Goodhart 回避原則に従い「合格条件であり最適化目標ではない」と注記する

### 4.2 ②B — カオスの出現制約

- **3F以降限定**・**1フロア同時1体まで**
- 本筋（ゲートへの必経路候補）ではなく**行き止まり／強敵枠側に配置** — カオスとの遭遇は常にプレイヤーの選択となり、「読めない敵」が理不尽ではなく賭けになる
- フロア生成規則（floors.json まわり）と game_design の敵配置節に反映

### 4.3 ⑤B — 読み宣言の段階解放

- **1Fでは非表示、2F到達で解放**
- 序盤の認知負荷を段階化しつつ、中盤の「新しい遊びが増えた」演出を兼ねる
- 「戦闘結果に影響しない独立の賭け」という純度は現状維持（報酬の情報還元化＝⑤Aは保留、§5）

## 5. 保留・不採用とした代替案（将来の再検討用）

| 項目 | 内容 | 状態 |
|---|---|---|
| ①A 予兆テレグラフ | 一部の敵に「次ターン強打」の気配変化を持たせ、受けの見せ場を保証 | 保留 — まず①Bのシミュで攻撃支配が実際に起きるか測ってから要否判断 |
| ①C 配置ルール | 強打頻度の高い「賭け」タイプを各フロア本筋に必ず1体 | 同上 |
| ②A カオスのラン内一貫性 | ラン内では手が一貫し、序盤数ターンが「観測フェーズ」になる。スカウトで今ランの傾向を買える | 保留 |
| ④B 卓選択 | ロール前に「堅い卓／勝負卓」を選ばせ、分散への主体性を挟む | 保留 — ゲート保証との役割整理が必要 |
| ④C 段階開示演出 | 出目を「特殊か→無傷か→小か大か」と段階的にめくる。確率不変の納得感改善 | 保留 — いつでも追加可能な独立オプション |
| ⑤A 的中の情報還元 | 読み宣言の的中でテルが読みやすくなる等、報酬を「情報」に変換 | 保留 |
| ③補 図鑑・称号系 | ディーラー調書の完成度、到達記録、初遭遇コレクション | 保留 — 登攀ポイント制で③の緊急度が下がったため |
| 細部: 1Fの見本市化 | 固定3体をタイプ見本市にし、1体は受けが決まる教師役に。1F限定の無料スカウト1回 | 未決 |
| 細部: 敵の signature 欄 | 全36体に「一言で言える癖」を必須記載し、タイプ内個体差のチェックリストにする | 未決 |
