# 0001. バックエンドに Python + FastAPI を採用する

## Status

Accepted

## Context

- ゲームロジックは全て Python に集約し、bot シミュレーターと UI が同一の `game_engine` を共有する方針（§22.3 設計原則）。この原則を満たすには、ロジックを持つバックエンドを Python で書く必要がある。
- Web API フレームワークの選定にあたり、API 仕様の自動生成・型安全・ターン制ゲームに耐える非同期処理が求められる（§22.2 技術選定一覧）。

## Decision

- バックエンドは **Python + FastAPI** を採用する（§22.2）。
- 全ゲームロジックは Python 側に置き、React では計算・勝敗判定を行わない（ADR 0002 参照）。

## Consequences

- Swagger（OpenAPI）が自動生成され、API 仕様が実装と同期しやすい（§22.2 選定理由）。
- Pydantic による型安全なリクエスト/レスポンス定義が可能（§22.2）。
- 非同期対応によりターン制の I/O を素直に扱える（§22.2）。
- ロジックが Python に一本化されるため、API と bot シミュレーターで同じエンジンを共有できる（§22.3）。
- 現時点で移行先は想定しない（§22.2 将来の移行先＝「—」）。
