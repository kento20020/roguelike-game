# 0002. ゲームロジックはサーバ権威（server-authoritative）とする

## Status

Accepted

## Context

- 将来の技術移行コストを最小化しつつ、クライアント改ざん・不正遷移を防ぐ必要がある（§22.3 設計原則）。
- bot シミュレーターと UI でロジックを分岐させず、同一エンジンで検証・プレイの両方を成立させたい（§22.3）。

## Decision

§22.3 の設計原則に従い、以下をサーバ権威として確定する。

- ゲームロジックは**全て Python** に置き、React は計算・勝敗判定を行わず、サーバが返す**完全なゲーム状態を表示**するだけとする。
- 同一の `game_engine` を API と bot シミュレーターが共有する。
- UI は `available_actions` を**操作可否の正本**とする（フロントに独自の条件分岐を持たせない）。
- phase 不整合の拒否は**サーバ側で必ず行う**（§25.4）。

## Consequences

- bot シミュレーターと UI が同じエンジンを共有でき、検証結果が実プレイと一致する（§22.3）。
- フロントの条件分岐を排除でき、`available_actions` に含まれない操作は非表示/disabled になる（§25.3）。
- クライアント改ざん・不正遷移に対する防御がサーバ側で担保される（§25.4）。
- React 側は状態表示に専念するため、差分計算を持たない（各レスポンスが完全状態を返す前提）。
