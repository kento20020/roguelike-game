カジノを舞台にしたローグライトの**ラン終端の3画面**を、1つのインタラクティブなプロトタイプとして作ってください。上部に「フロア遷移 / クリア / 敗北」を切り替えるトグルを置き、同じ画面内で3状態を行き来できるようにしてください（探索・戦闘画面は既存なので作りません）。

## 世界観・ムード
高層のカジノタワー。煤けた紙のような暗色地、立ちのぼる残り火とヘイズ、朱（行動・危険）と真鍮（賭け・勝利）のアクセント。荘厳で湿度のある「カジノ・ノワール」。チャラさは無く、賭けの緊張と幕引きの余韻。

## 必ず踏襲する視覚言語（既存画面と完全に揃える）
カラートークン（CSS変数でそのまま使用）:
```
--paper:#15120E; --paper2:#1F1B15; --paper3:#2A241B; --felt:#171814;
--ink:#F1ECE0; --ink2:rgba(241,236,224,0.60); --ink3:rgba(241,236,224,0.33);
--rule:rgba(241,236,224,0.13); --rule2:rgba(241,236,224,0.24);
--accent:#C85A2A; --accent2:#9A3A14; --accentSoft:rgba(200,90,42,0.14);
--brass:#C9A24B; --brassSoft:rgba(201,162,75,0.12); --danger:#C7402A; --moss:#5E8A66;
```
フォント: 大見出し/章は serif（Instrument Serif + Noto Serif JP）、UIは sans（Geist + Noto Sans JP）、**数値は必ず mono（JetBrains Mono, tabular-nums）**。
背景: 紙ノイズ＋ヘイズ円2枚（ゆっくりドリフト）＋残り火が下から立ちのぼる。中央に向けたビネット。
細部: ラベルは sans 10px・letter-spacing 広め・大文字。主ボタンは朱(--accent)塗り、副ボタンはゴースト枠。パネルは --felt 面に薄い内側ハイライトと深い影。

これら3画面は**全画面・共通ヘッダー無し**（ランの幕引きとして画面全部を使う）。単一カラム中央寄せ、最大幅 約560px（決算カードのみ約640px）。デスクトップ密度優先。

## 画面1：フロア遷移
ゲート（関門）を抜けて次の階へ進んだ一拍の幕間。短く、すぐ次へ行ける。
- 中央に大きな章番号と章名（serif）。「2F ▸ 3F」のように階を移る表示。
- ゲートの出目バッジ（例「無傷で通過」=--moss ／「大ダメージ」=--danger）。被弾時は HP の減少を差分で（例 −12, --danger）。
- 進行ドット（1F…5F、到達点を真鍮で点灯）。
- 主ボタン「次の階へ」。
- 演出: 真鍮のグローが上へ抜け、章タイトルがふわっと立ち上がる（0.1秒程度の遅延フェード）。

## 画面2：クリア（5F頂上の関門を突破＝全制覇）
ラン全体の決算を見せ、祝祭しつつ次へ送り出す。
- 大見出し「制覇」（serif・真鍮グロー）。小さく seed を mono で添える。
- 決算カード（--felt 面）。数値は全て mono/tabular-nums、上から順に出る:
  - 到達 5/5、総ターン数、最終HP（hp/max）。
  - 稼いだチップ、使ったチップの内訳（偵察/小回復/大回復/攻撃強化/関門保証/引き直し を小さな行 or バーで）。
  - 撃破数、取得した技（既存のヘッダーにある技ピルと同じ見た目の pill で並べる）。
- 報酬バナー「＋1 強化ポイント」（最後に光って出る）。
- **恒久強化の割り振りを同じ画面内に置く**（GDD §26.6: クリア画面＝決算＋強化割り振り）。5項目を行で並べ、各行に現Lvと[＋]ボタン：+max_hp / +攻撃 / +初期チップ / +チップ獲得率 / -sinkコスト。残ポイントを上に表示。
- 主ボタン「次のランへ」、副ボタン「タイトルへ」。
- 演出: 真鍮の残り火を多めに、数値はカウントアップ、最後に +1pt。

## 画面3：敗北（パーマデス）
何で終わったかを簡潔に突きつけ、再走の動線だけ残す。湿っぽくしすぎない。
- 大見出し「敗北」（serif・--danger）。残り火は朱、背景は沈める。
- 死因の一文を最大で：「3F『◯◯』で 関門の大ダメージ に倒れた」。
- 簡易戦績（クリアより控えめ）: 到達フロア、総ターン、撃破数、稼いだチップ。
- 主ボタン「もう一度」。
- 演出: 朱の残り火が一度爆ぜて沈み、見出しが遅れて現れる。

## ダミーデータ（スロットを正しく作るための仮値。実際はバックエンドが供給）
- フロア名（`floors.json` 正本）: **1F チュートリアル / 2F / 3F / 4F / 5F 頂上**。装飾的な固有名は無い（番号＋1F/5Fのみタグ）。ゲート＝**胴元の関門**。
- 方向: **タワーを登る**（5F＝頂上が最深＝最終ボス）。遷移は「2F ▸ 3F」のように上へ。
- 遷移: 到達=3F、出目=大ダメージ、HP 64→52（−12）。
- クリア: 総ターン 38、最終HP 41/130、稼ぎ 420、撃破 11、技=見切り・反射・好機、seed=7。
- 敗北: 到達 3F、総ターン 21、取得技=見切り・反射・重装甲。

技ピル・HPバー・主/副ボタンは既存の探索/戦闘画面と同じ部品として作ってください（後でReactの共通コンポーネントに落とします）。アニメは既存と同系統（フェードアップ／残り火）でまとめ、新規エフェクトは最小限に。

## 取り込み後にこちらでやること
1. 生成 `.dc.html` を `design/` に保存。
2. 視覚言語が既存と一致しているか差分確認（トークン／フォント／背景）。
3. React 化時、共通部品（Button / Panel / HPBar / ModPill / EmberBackground / StatRow）を抽出し、エンド3画面＋既存2画面で共有。
4. 各画面を snapshot のデータ契約（`spec_end_and_transition.md`）に結線。
